# SO-ARM100 + ROS 2 Jazzy + MoveIt (แขนขยับตาม simulator)

ส่วนแขนของหุ่น RoboCup@Home สำเนาที่ใช้งานจริงอยู่บน Jetson ที่ `~/so100_ws/src`
- `so100_driver`: คุยกับมอเตอร์ STS3215 โดยตรง, ส่ง `/joint_states`, รับคำสั่งจาก MoveIt, calibrate, IK หยิบ-วาง, API `/arm/*`
- `so100_interfaces`: action/msg ของ API (ดู [API.md](API.md))
- `so100_moveit_config`: โมเดล 3D (URDF), ค่าตั้ง MoveIt, RViz, launch (`camera:=true` = ทดสอบกับกล้อง Xtion)
- `calibration.json`: ค่า calibrate ของแขนตัวที่ใช้แข่ง (ใช้ได้กับแขนตัวนี้ตัวเดียว)

## ติดตั้งบน Jetson (ROS 2 Jazzy) จาก repo นี้
```
git clone -b arm-system https://github.com/clytie0x/robocup-home-education.git ~/robocup-home-education
mkdir -p ~/so100_ws/src && cd ~/so100_ws/src
ln -s ~/robocup-home-education/arm/so100_driver ~/robocup-home-education/arm/so100_interfaces \
      ~/robocup-home-education/arm/so100_moveit_config .
cp ~/robocup-home-education/arm/{start_arm.sh,stop_arm.sh,start_display.sh,trial.sh} ~/so100_ws/
cp -n ~/robocup-home-education/arm/calibration.json ~/so100_ws/calibration.json   # ไม่ทับของเดิม
cd ~/so100_ws && rosdep install --from-paths src --ignore-src -y      # ROS/MoveIt/python deps จาก package.xml
sudo apt install xvfb openbox x11vnc novnc websockify                 # จอเสมือนสำหรับ RViz ผ่านเบราว์เซอร์
colcon build --symlink-install
~/so100_ws/start_arm.sh                     # แขนจริง + MoveIt + API   (hardware:=sim = ไม่มีแขน)
```
ผู้ใช้ต้องอยู่กลุ่ม `dialout` เพื่อเปิด `/dev/ttyACM0` ได้ (`sudo usermod -aG dialout $USER` แล้ว log out/in)

## เปิดใช้งาน (บน Windows)
ไฟล์ `.cmd` ด้านล่างอยู่ในเครื่องคนดูแลแขนเท่านั้น (มี key/IP ส่วนตัว จึงไม่อยู่ใน repo) คนอื่นใช้ `start_arm.sh` บน Jetson แทน

| ไฟล์ | ทำอะไร |
|---|---|
| `D:\Robot\Start-SO100.cmd` | แขนจริง + MoveIt + RViz (ลากลูกบอลแล้วกด Plan & Execute) |
| `D:\Robot\Start-SO100-Sliders.cmd` | แขนจริงขยับตามแถบเลื่อนของแต่ละข้อ |
| `D:\Robot\Stop-SO100.cmd` | ปิดโปรแกรมบน Jetson (แขนยังค้างแรงที่ท่าสุดท้าย) |

ดับเบิลคลิก ใส่รหัส Jetson แล้วรอ เบราว์เซอร์จะเปิด RViz ให้เอง (`http://localhost:6080/vnc.html`)
**ต้องเปิดหน้าต่างดำทิ้งไว้** ตลอดที่ใช้ RViz ถ้าปิดไป RViz ในเบราว์เซอร์จะหลุด แต่แขนยังค้างแรงอยู่

## แผงปุ่ม "SO-100 ควบคุมแขน" (หน้าต่างเล็กข้าง RViz)
- **🔓 ปลดแรง — ขยับแขนด้วยมือ**: ถามยืนยันก่อน (ต้องประคองแขน เพราะแขนจะร่วง) แล้วปลดแรงทุกข้อ
  ระหว่างนี้โมเดลใน RViz ขยับตามแขนจริงที่คุณจับขยับ
- **🔒 ล็อกแรงที่ท่าปัจจุบัน**: เปิดแรงค้างท่าที่แขนอยู่ (Plan & Execute ก็ล็อกให้เองเหมือนกัน)
- **■ หยุดการเคลื่อนที่**: หยุดและค้างท่าตรงนั้น
- ด้านล่างแสดงไฟ อุณหภูมิ max_lag และ fault

## ใช้ RViz สั่งแขน

0. ตัววางแผนเริ่มต้นคือ OMPL ไม่ต้องตั้งอะไร (ในที่โล่งให้เส้นทางตรงในมุมข้อ)
   ถ้าอยากให้ทุกข้อเดินเส้นตรงถึงพร้อมกันแบบเป๊ะ: แท็บ Context → ช่องแรกเลือก pilz_industrial_motion_planner
   แล้ว **ต้อง** เลือก `PTP` ในช่องที่สอง (ถ้าเป็น `<unspecified>` จะวางแผนไม่ได้)
1. ทุกคำสั่งแรกจะ **เปิดแรงมอเตอร์ที่ท่าปัจจุบัน** อัตโนมัติ
2. แท็บ **Planning**: `Planning Group = arm`
3. ลาก **ลูกบอลสีฟ้า** ที่ปลายมือไปยังจุดที่ต้องการ (โมเดลสีส้มจาง ๆ คือท่าเป้าหมาย)
   - แขนมี 5 ข้อ จึงคุมได้แค่ตำแหน่งปลายมือ ทิศของมือ (ก้ม/หมุนข้อมือ) ปรับเองในแท็บ **Joints**
   - หรือเลือก `Goal State` = `ready` / `rest`
4. กด **Plan & Execute** แขนจริงจะเดินตามเส้นทางที่เห็น
5. `Velocity Scaling` เริ่มที่ 0.10 (ช้า ปลอดภัย) เพิ่มได้ถึง ~0.5 (ไฟ 12V 2A ไม่ควรเร็วกว่านั้น)
   `Accel. Scaling` ตั้ง **0.5–1.0** (ค่าต่ำทำให้เร่ง/ชะลอนาน → ช่วงเดินช้ามาก ๆ ที่ทำให้สั่น)
6. กริปเปอร์: เปลี่ยน `Planning Group = gripper` → `Goal State = open` หรือ `close` → **Plan & Execute**
   ตอนหุบใส่ของ กริปเปอร์จะหยุดเมื่อหนีบโดนของ และหนีบค้างด้วยแรง 50%
7. หยุดกลางทาง: ปุ่ม **Stop** ใน RViz (แขนหยุดค้างแรงตรงนั้น)

ท่าที่ MoveIt บอกว่าวางแผนไม่ได้ (สีแดง / "Unable to solve") = แขนเอื้อมไม่ถึงหรือจะชนตัวเอง → ลากใหม่ใกล้ตัวขึ้น

## ทดสอบหยิบ-วางด้วย IK (โหมด MoveIt)
ใน RViz มี **กล่องฟ้า = ของ** และ **กล่องม่วง = จุดวาง** (ลากบนโต๊ะได้ วงแหวนรอบกล่อง = หมุน)
1. วางของจริงบนโต๊ะ แล้วลากกล่องฟ้าไปตรงนั้น (แผงปุ่มบอกพิกัด "หน้า/ซ้าย" จากแกนหมุนฐาน
   ใช้ตลับเมตรวัดเทียบได้: หน้า = ทิศที่แขนชี้ตอนฐาน 0°, ซ้าย = บวก, ขวา = ลบ)
2. ใส่ขนาดของในแผงปุ่ม `ลึก (หน้า-หลัง) / กว้าง (ซ้าย-ขวา) / สูง` เป็นซม. → **ใช้ขนาดนี้**
3. ลากกล่องม่วงไปจุดที่จะวาง บรรทัดล่างสุดบอก ✔ หยิบได้ / ✘ เหตุผล (เช่น เอื้อมไม่ถึง, ของกว้างเกินก้าม)
   **พื้นสีเขียวบนโต๊ะ = จุดที่วางของชิ้นนี้ได้** (คำนวณใหม่เองทุกครั้งที่ย้าย/หมุนกล่องฟ้า เปลี่ยนขนาด หรือหมุนกล่องม่วง ใช้เวลาไม่กี่วินาที)
4. **▶ หยิบ-วาง**: ไปเหนือของ → อ้าก้าม → ลงตรง ๆ → หนีบ (ถ้าหุบสุด = จับพลาด ถอยขึ้นแล้วหยุด)
   → ยก → ไปเหนือจุดวาง → วาง → ปล่อย → ถอยขึ้น → ท่า ready  (กล่องฟ้าย้ายตามไปที่ใหม่เอง)
5. **☝ แตะจุดกล่องฟ้า**: หุบก้ามแล้วพาปลายก้ามไปค้างเหนือโต๊ะ 1 ซม. ตรงกลางกล่องฟ้า ใช้วัดความแม่น
- ระยะที่หยิบจากด้านบนได้ (ของ 3×3×5 ซม.): หน้า ~12–28 ซม., ซ้าย/ขวา ถึง ~20 ซม. ไกลกว่านั้นจะจับเฉียง
- ก้ามรับของกว้างได้ถึง ~6.5 ซม. (ด้านที่ก้ามหนีบ) โปรแกรมเลือกด้านแคบให้เอง
- ทุกท่าในแผนถูกเช็กกับโต๊ะทั้งตัวแขน (จากโมเดล 3D): ข้อแขน/ข้อมือห่างโต๊ะ ≥ 1.2 ซม., ก้าม ≥ 0.4 ซม.
  ถ้าทำไม่ได้จะขึ้น ✘ แทนการไปชน  ถ้าหยุดกลางทาง โปรแกรมลบของออกจาก MoveIt ให้ RViz สั่งแขนต่อได้
- ข้อมือก้ม (wrist_flex) calibrate ไว้ได้แค่ +34° ทำให้บางจุดชี้ลงตรง ๆ ไม่ได้ (โปรแกรมเอียง 5–25° ให้แทน)
- ค่า: ความเร็วช่วงเส้นตรง `line_speed` 0.03 m/s, MoveIt `velocity_scaling` 0.3
  (`ros2 param set /so100_pick_place line_speed 0.02`)
- โค้ด: `so100_driver/ik.py` (IK แบบคำนวณตรง + วางแผนท่าจับ, test ใน `test/test_ik.py`),
  `pick_place_node.py` (กล่องใน RViz, ลำดับหยิบ-วาง)

## API ให้ส่วนอื่นเรียกใช้ (`/arm/pick`, `/arm/place`, `/arm/pick_place`, `/arm/home`, `/arm/rest`, `/arm/stop`, `/arm/torque`, `/arm/state`)

## ทดสอบกับกล้อง ASUS Xtion (แขนจำลอง + กล้องจริง)
วางกล้องได้ 2 แบบ (**Xtion วัดระยะได้ตั้งแต่ ~0.6 ม.** ใกล้กว่านั้นไม่มีข้อมูล) เสียบ USB เข้า Jetson
- **แบบต่ำ (ไม่ต้องมีที่วางสูง):** ตั้งบนโต๊ะ (หรือกล่องสูง 10–20 ซม.) **ด้านหน้าแขน ห่างแกนฐาน ~1 ม.** หันหน้าเข้าหาแขน ก้มลงนิดหน่อย
  กล้องเห็นแต่ด้านหน้าของของ โปรแกรมถือว่าของกลม/สี่เหลี่ยมจัตุรัส (ลึก = กว้าง) แล้วดันจุดกลางไปด้านหลังให้เอง
- **แบบสูง (แม่นกว่า):** สูงจากโต๊ะ ~65 ซม. หลังแขน ~30 ซม. ก้มลง ~50° มองข้ามแขนไปข้างหน้า
- ติดเทปให้นิ่ง ขยับกล้องเมื่อไรต้อง calibrate ใหม่
1. เปิด: ดับเบิลคลิก `D:\Robot\Start-SO100-CameraSim.cmd` (= `start_arm.sh hardware:=sim camera:=true` แขนจริงไม่ขยับ)
2. **Calibrate ครั้งแรก / ทุกครั้งที่ขยับกล้อง** ใช้ของแคบทรงกลม (กว้าง < 9 ซม. เช่น กระป๋อง ขวดน้ำ) วางบนโต๊ะชิ้นเดียว
   - วางที่จุด A: หน้าแกนฐาน 20 ซม. ซ้าย 10 ซม. → `ros2 service call /camera_test/calib_a std_srvs/srv/Trigger`
   - ย้ายไปจุด B: หน้า 20 ซม. ขวา 10 ซม. → `ros2 service call /camera_test/calib_b std_srvs/srv/Trigger`
   - ตอบกลับตำแหน่งกล้องที่คำนวณได้ และความคลาดของระยะ A–B (ควร < 1 ซม.) ค่าเก็บที่ `~/so100_ws/camera_calib.json`
   - เปลี่ยนจุดได้ด้วย parameter `spot_a`, `spot_b` = [หน้า, ซ้าย] เมตร
   - **ถ้ารู้ขนาดของ (เช่น กล่อง)** ตั้ง `ros2 param set /camera_test object_size "[0.12, 0.03, 0.03]"` (ยาว, กว้าง, สูง ม.)
     แล้วใช้ของชิ้นนั้น calibrate ได้เลย (หันด้านยาวเข้ากล้อง) กล้องหาแค่ตำแหน่ง/มุม ส่วนที่มองไม่เห็นเติมตามขนาดจริง
     และไม่นับสิ่งที่สูงเกินของ +4 ซม. (เช่น ก้ามแขนที่ห้อยอยู่) ค่าจำไว้ใน `~/so100_ws/camera_object_size.json`
3. วางของที่จะหยิบ (กว้างด้านใดด้านหนึ่ง ≤ 6.5 ซม.) แล้ว:
   - `ros2 service call /camera_test/objects std_srvs/srv/Trigger` ดูว่ากล้องเห็นอะไร (ตำแหน่ง/ขนาด)
   - `ros2 service call /camera_test/pick std_srvs/srv/Trigger` แขน (จำลอง) หยิบชิ้นที่ใกล้แขนที่สุด
   - `ros2 service call /camera_test/pick_place std_srvs/srv/Trigger` หยิบแล้ววางที่ `place_spot` (หน้า 22 ขวา 12 ซม.)
4. ใน RViz: จุดสีจากกล้อง + กล่องสีส้ม = ของที่กล้องเห็น เช็กว่ากล่องส้มทับของจริงใน point cloud และกล่องฟ้าของแขนไปตรงนั้น
- ไม่นับจุดภายในรัศมี `ignore_radius` (11 ซม.) จากแกนฐาน = ตัวแขนและแท่น และไกลกว่า `max_radius` (45 ซม.)
- ใช้กับแขนจริง: `start_arm.sh camera:=true` (แขนขยับจริง! ลองในจำลองให้ตรงก่อน)

## สั่งจากระบบเสียง (topic ที่ตกลงกับทีมเสียง)
| topic | ชนิด | ทิศทาง | ความหมาย |
|---|---|---|---|
| `/robot/carry_bag` | `std_msgs/Empty` | เสียง → แขน | หยิบของตรงกล่องฟ้า แล้วยกมาถือไว้ที่ท่า ready |
| `/robot/drop_bag` | `std_msgs/Empty` | เสียง → แขน | วางของที่ถืออยู่ตรงกล่องม่วง (ถ้ากล่องม่วงไกลเกิน วางคืนที่เดิม) แล้วปล่อย |
| `/robot/event` | `std_msgs/String` | แขน → เสียง | `grab_success` / `grab_failed` (ส่งหลังยกของขึ้น ~10–15 วิ, ระบบเสียงรอ 20 วิ), `drop_done` (ส่งทันทีที่ปล่อยของ ก่อนถอยแขน) / `drop_failed` |

ทดสอบโดยไม่ต้องพูด (บน Jetson, `ROS_DOMAIN_ID=42`):
```
ros2 topic echo /robot/event &
ros2 topic pub --once /robot/carry_bag std_msgs/msg/Empty "{}"
ros2 topic pub --once /robot/drop_bag std_msgs/msg/Empty "{}"
```
ตำแหน่งของยังมาจากกล่องฟ้าใน RViz (ยังไม่มีกล้อง)

## ความปลอดภัยที่โปรแกรมทำให้
- ทุกข้อถูกจำกัดในช่วงที่ calibrate (เว้นขอบ ~2°) และจำกัดความเร็ว
  ตอนเปิดโปรแกรม ช่วงใน MoveIt/RViz ถูกปรับให้ตรงกับ `calibration.json` อัตโนมัติ (ลากเกินช่วงจริงไม่ได้)
- MoveIt มีพื้นโต๊ะอยู่ต่ำกว่าฐาน 7.5 ซม. (ฐานวางบนแท่น) จะไม่วางแผนให้แขนลงต่ำกว่าโต๊ะ
  ถ้าย้ายแขนไปตั้งที่อื่น ตั้งใหม่ด้วย `table_z:=<เมตร>` (เช่น วางบนโต๊ะตรง ๆ ใช้ -0.003)
  แท่นที่ฐานวางอยู่ MoveIt ยังไม่รู้จัก
  แต่ยังไม่รู้จักสิ่งของบนโต๊ะ ถ้าต้องการ เพิ่มกล่องในแท็บ Scene Objects ของ RViz
- ตรวจจับการชน: ข้อตามหลังเป้าเกิน 8° (+0.25 วินาที × ความเร็วตอนกำลังเคลื่อน) นาน 0.5 วินาที
  → หยุดค้างท่าปัจจุบัน สั่งใหม่ได้เลย (บรรทัดสถานะ `/so100/status` แสดง max_lag)
- ไฟต่ำกว่า 10V เตือน, มอเตอร์ร้อนถึง 60°C หยุด
- โปรแกรมไม่ปลดแรงเอง (กันแขนร่วง) ปลดได้จากแผงปุ่ม หรือ **ประคองแขนก่อน** แล้วรันบน Jetson:
  `ros2 service call /so100/enable std_srvs/srv/SetBool "{data: false}"`
  (ก่อนใช้ ros2 ใน terminal: `source ~/so100_ws/install/setup.bash; export ROS_DOMAIN_ID=42`)

## ทำไมเลิกสั่น
แอปเดิมสั่งมอเตอร์ให้วิ่งเองด้วยความเร็ว 60 (≈5°/วินาที) acc 5 และ P=32 → แขนกระตุกแบบติด-ไหล โดยเฉพาะขาลง
ตอนนี้ใช้ค่าแบบ LeRobot: P16/I0/D32, acc 254 แต่ฐาน P12 และ dead zone 3 ที่ฐาน/ไหล่/ศอก, 1 ที่ข้ออื่น
(ทดลอง A/B บนแขนจริง 7 พ.ย.: D64, P24, P32 แย่ลง; ฐาน P12 ดีที่สุด, P8 อ่อนเกิน; dead zone 3 ดีที่สุด;
เฟือง STS3215 คลอนตามสเปก ~0.5° ฐานจึงไวต่อ P มากที่สุด; การทดลองเก่าเคยตั้ง 8
ทำให้ตอนเคลื่อนช้ามอเตอร์กระโดดทีละ 0.7° = สั่น) เขียนลง RAM ทุกครั้งที่เปิด ไม่แตะ EEPROM
แล้วคอมส่งเป้าหมายทีละนิด 50 ครั้ง/วินาทีตามเส้นทางนุ่ม ๆ ของ MoveIt + ชดเชยแขนห้อยจากน้ำหนัก
ผลวัดบนแขนจริง: ส่าย ≤ ~1°, คลาดเป้า ≤ 1.4°, ไฟ 12.1–12.3V ตลอด

## ปรับค่ามอเตอร์ระหว่างใช้งาน (เขียน RAM ทันที ไม่ถาวร)
```
ros2 param set /so100_driver servo_dead_zone "[3,3,3,1,1,1]"   # ID1..6
ros2 param set /so100_driver servo_d "[32,32,32,32,32,32]"
ros2 param set /so100_driver servo_p "[12,16,16,16,16,16]"
~/so100_ws/trial.sh "<p>" "<d>" "<dead_zone>"   # ตั้งค่าแล้วรันท่าช้าของฐาน/ไหล่/ศอก + วัดผล (แขนขยับ!)
```

## Calibrate ใหม่ (เมื่อถอด/ประกอบแขน หรือเปลี่ยนมอเตอร์)
ปิดโปรแกรมก่อน (`Stop-SO100.cmd`) แล้วบน Jetson:
```
cd ~/so100_ws && source install/setup.bash
ros2 run so100_driver calibrate status             # ดูค่า (อ่านอย่างเดียว)
ros2 run so100_driver calibrate release            # ปลดแรง (ประคองแขนก่อน!)
ros2 run so100_driver calibrate zero               # แขนอยู่ท่าพับ = ท่าศูนย์ (ดู rest_pose_reference.png)
ros2 run so100_driver calibrate sweep 30 shoulder_pan   # ทีละข้อ: หมุนจนสุดสองด้านใน 30 วินาที
ros2 run so100_driver calibrate flip <joint>       # ถ้าข้อไหนใน RViz หมุนกลับทิศกับแขนจริง
```
ค่าเก็บที่ `~/so100_ws/calibration.json` (มีสำรอง `.bak`)

## ทดสอบ

- `ros2 run so100_driver motion_test` ชุดท่าใหญ่ + วัดการสั่น (แขนจะขยับ! เคลียร์พื้นที่ ~45 ซม.)
